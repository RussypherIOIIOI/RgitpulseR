# Release security evidence — updated November 3, 2026

These are dependency audit results, not a comprehensive security assessment.

## Patched Python runtime

The original hashed export contained certifi 2026.7.22. Auditing that immutable
baseline failed on GHSA-6q48-6c7w-9gw2 / PYSEC-2026-4320. The audit displayed two
rows for the same advisory, not two independent defects. The
[official advisory](https://github.com/advisories/GHSA-6q48-6c7w-9gw2) recommends
2026.10.19 or later and rebuilding images containing the bundle.

Selective resolution with uv 0.10.10 chose certifi **2026.10.23**. No other Python
dependency changed. Hashes were generated by uv, not edited. Reproduce:

```powershell
uv lock --check
uv export --frozen --no-dev --no-emit-project -o requirements.lock
git diff --exit-code -- requirements.lock
uvx --from pip-audit==2.10.1 pip-audit --requirement requirements.lock --require-hashes --progress-spinner off
```

After committing the generated export, the diff command should return zero.
The updated audit returned **No known vulnerabilities found**. CI executes the
same audit outside the production runtime. Docker was rebuilt and its installed
certifi version was read back as 2026.10.23. This does not audit Debian packages,
the base image's bundled pip, or every build dependency.

## npm runtime and development scope

`npm audit --omit=dev` returned **zero findings**. Full `npm audit` returned
**16 moderate dependency entries**, all deriving from the single
[minimatch pattern amplification advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).
Installed development trees contain minimatch 3.1.5 and 10.2.6; the advisory's
patched version is 11.0.1. These are used by ESLint/plugins and TypeScript tooling.
They are omitted by `npm ci --omit=dev` in the runtime image.

No blanket major-version override was applied: replacing old minimatch interfaces
across ESLint/plugins would require compatibility work. The audit solver proposes
obsolete ESLint 4.0.0 / eslint-config-next 0.2.4 downgrades. Those were rejected;
neither `--force` nor advisory suppression was used. The owner accepted this
documented development-only residual in the November 3 ELMO launch approval.
Do not lint attacker-supplied glob patterns. Revisit when upstream compatible
patches are available; runtime findings continue to fail CI.

## Deployment boundaries

The active ELMO candidate uses a dedicated private PostgreSQL 18 container with no
published database port. The web service receives only a limited reader DSN file;
explicit operations receive a separate owner DSN. The reader grant script refuses
elevated roles, memberships, object ownership, CREATE, and effective write grants
through PUBLIC or column privileges. Windows secret files are protected by ACLs,
not claimed encrypted. Local role/restart/recovery contracts passed. Approved
production credentials/SQL and public routing were applied; actual reader access,
write rejection, public 403 refresh and restart persistence were verified.
See [live evidence](live-release.md) and [selfhost scope](selfhost.md).

Web refresh stays disabled, synthetic data needs no GitHub token, and production
startup does not run automatic schema/seed operations. The approved dedicated
production database and public deployment now exist. No GitHub token, live
ingestion or scheduler is enabled. Reboots, off-host/fresh-cluster recovery and
production rollback remain unverified; dependency audits are not comprehensive
security or availability certification.
